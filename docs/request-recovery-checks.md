# D8：请求恢复与本地读写异常处理

日期：2026-10-16。环境：WSL Ubuntu。
分支：feat/request-recovery；记录时提交、推送及合并尚待完成。

## 当前实现

agent.py 新增 request_model(request_body)，ask_agent 的每一轮通过它请求模型。连接失败或超时最多尝试两次；HTTP 错误、JSON 解析错误及响应顶层格式错误不自动重试。请求设置 timeout=(5, 60)，分别控制连接与读取等待，不是整个请求的总时限。原模型交互上限仍为四轮，和每轮网络尝试上限分别计数。

cli.py 在普通问答处分类捕获 JSONDecodeError、RequestException、ValueError，失败后继续输入，成功后才接收返回历史并增加成功次数。命令分发外层捕获 OSError、ValueError，覆盖熟悉库、复习与资料读写异常，以及模型工具读取文件产生的 OSError。登记/撤销函数未成功返回时，不执行后续成功提示；末尾熟悉提示读取失败时，已输出的回答保留。

现有输入、名称解析、工具循环、熟悉状态及每日复习核心逻辑沿用原实现。

## 检查范围与证据

两个实践单元均已提供集中模拟检查命令及正常入口检查。用户分别反馈“没有问题，我们继续”。助手本次只读核对实际修改，没有重跑模型、模拟检查或完整回归；未提供的逐项终端日志不补造。以下是检查约定，不是助手独立运行的逐项结果。

| 场景 | 约定预期 |
| --- | --- |
| 正常请求 | 一次成功并返回包含 message 的字典 |
| 首次超时、第二次成功 | 尝试两次后返回 |
| 持续超时或断连 | 尝试两次后抛出，由 CLI 报告并继续输入 |
| HTTP 错误 | 不自动重试 |
| 无效 JSON / 缺少 message 字典 | 报告错误，不采纳失败问答历史 |
| 失败后执行本地命令与成功问答 | CLI 继续运行，失败不增加成功问答次数 |
| 登记或撤销读写失败 | 报告原因，不输出成功提示 |
| 熟悉库 JSON 损坏 | 报告原因，不自动重置或保存空库 |
| 复习 / 查看 / 工具读取失败 | 报告原因并继续输入 |
| 回答后熟悉提示读取失败 | 已输出回答保留，继续输入 |
| 正常熟悉列表与资料查看 | 原有正常行为继续可用 |

模拟检查通过替换请求或文件操作构造错误，不需要关闭模型服务、修改系统日期或破坏真实个人文件。

## 学习与交付边界

- 用户亲手接入请求辅助函数、编写分类捕获及外层异常处理；请求函数参考、语法说明和集中检查命令由助手提供，属于答案辅助实践。
- 按用户反馈登记本日约定功能检查正常；独立理解、复现与迁移尚未验证。
- 外层异常处理只负责提示和继续输入，不自动修复坏文件，也不保证写入失败时原文件完全不变；原子写入及故障恢复不属于本日成果。
- 深层工具响应仍可能存在尚未处理的格式问题，本日不声称所有异常均能恢复。
- 日志/Markdown 导出、基础 CI、固定题集评价与新环境发布复现仍待完成；D5 的回答质量问题继续保留。
