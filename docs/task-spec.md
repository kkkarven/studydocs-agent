# 首版任务约定

本文定义产品的预期行为与初始评价场景，不表示这些功能已经实现。

## 1. 用户输入

支持 C、C++、Python 的语法问题，以及常用 Python 库的接口用法。输入可以是条目名称、声明或调用片段，也可以是相关疑问。

建议提供语言、库和具体疑问，例如“Python print 的作用”“C 中 int *a[] 的含义”。不同语言可能有相同名称；无法判断语言、库或使用场景时，先要求补充，不能凭猜测给出确定结论。

用户可以提供相关代码与版本；版本或作用域影响解释时，应标明所依据的版本和场景。不要求每个简单问题都填写一套固定格式。

## 2. 语法回答

默认回答简短、聚焦当前问题，包含：

- 该语法或接口的用途。
- 基本形式及主要组成；接口涉及参数与返回值时说明它们。
- 一个短示例，以及示例会产生什么结果。
- 当前问题相关的易错点；有版本差异时说明适用版本。
- 使用本地资料时附可定位的文件、标题或行号出处。

示例应定义所需变量并说明必要前提，不能把未声明变量或省略号占位的片段称为可直接运行的完整示例。首版不自动执行模型生成的代码。

问题含有错误前提时，应先指出并澄清。例如 Python 默认没有名为 printf 的内置函数，不能因此声称 print 没有作用。

## 3. 资料检索与依据不足

保留对指定个人 Markdown 语法资料的检索与读取。首版以少量人工核对条目为起点，逐步增加；不要求预先覆盖所有语言和库。

有匹配资料时，应依据资料解释、给出出处，并检查关键结论和示例是否得到支持。引用存在并不自动证明整段回答正确。

没有匹配资料时，可以提供简短的待核对说明，但必须明确标注“缺少本地资料依据，以下说明尚未核对”，不能编造出处。不确定的内容应明确说明，必要时要求用户补充信息；不能把“基础用法”当作准确性保证。

模型自身知识、资料依据和个人熟悉状态分别处理。资料检索失败时，说明工具失败，不能伪装为资料中没有答案。

## 4. 熟悉登记与提示

拟定的应用内命令：

| 输入 | 预期行为 |
| --- | --- |
| /登记 Python print | 将明确的 Python print 条目标记为用户自述熟悉，保存到本地 |
| /熟悉库 | 显示已登记的条目 |
| /取消登记 Python print | 撤销熟悉状态，保留原有语法资料 |

/登记 必须是明确命令。普通问句中出现“登记”二字或模型输出这两个字，不触发写入。无法确定具体条目时先澄清，不能记录模型猜测的结果。

匹配对象是语言或库中的语法条目，不要求用户每次输入完全相同的句子。首版依靠明确名称与少量人工别名匹配；同名但属于不同语言或库的条目不能混为一项。

重复登记不产生重复条目，重新启动后仍保留状态。登记表示用户明确自述熟悉，模型不能自动判断或更改掌握状态。

查询已登记条目时，仍正常解释用法和示例，回答尾部提示“该条目已在你的熟悉库中”。提示依据本地真实记录生成。未登记或已经撤销的条目不显示这条提示。

## 5. 每日复习

使用应用内命令 /复习，从已登记条目中随机抽取当天的一组，默认 3 条，组内不重复。

- 熟悉库为空：明确提示尚无可复习条目，不能编造题目。
- 条目数为 1 或 2：全部返回，不复制条目凑满 3 条。
- 条目数至少为 3：返回 3 个不同的已登记条目。
- 同一天再次打开：可恢复当天的一组；下一天首次触发时重新抽取，新组允许与前一天重合。
- 先展示待回忆条目，再允许查看已有说明和示例；不自动认定用户掌握。
- 已撤销的条目不再作为复习候选。

每日功能在应用打开后由用户触发；首版不包含关闭程序时的后台主动提醒。私人熟悉库与复习记录保留在本地，不进入公开示例。

## 6. 初始评价场景

下面是未来功能的检查标准。前提中的资料与状态需要在对应实现阶段准备，不代表当前已经存在或已经通过。

| 场景 | 前提 | 用户输入或操作 | 可观察的通过标准 |
| --- | --- | --- | --- |
| E01：正常查询 | 有核对过的 Python print 资料；未登记该条目 | “解释 Python print 的用途，并给一个简短示例” | 说明输出文本的用途；示例结果正确；附资料出处；没有熟悉提示 |
| E02：熟悉提示与重复登记 | E01 的资料可用 | 明确登记 Python print 两次，再查询其用途 | 熟悉库只有一个对应条目；仍正常回答；尾部显示熟悉提示；重启后登记保留 |
| E03：名称混淆 | 有 Python 内置函数与字符串格式化的核对资料 | “Python 中 printf 的作用是什么？” | 区分默认内置 print 与未定义的 printf；若讨论格式化，不否认 Python 的百分号字符串格式化；不编造未提供的第三方库 |
| E04：缺少资料 | 本地没有 C 指针数组的资料 | “C 中 int *a[] 是什么意思？” | 明确缺少本地依据；不编造出处；给说明时保留待核对标记；不无依据扩展出多维、动态数组等结论 |
| E05：空库复习 | 熟悉库为空 | /复习 | 明确说明无可复习条目；返回 0 个复习条目 |
| E06：不足三条 | 熟悉库只有 Python print 和 Python 字典按键取值两项 | /复习 | 只返回这两项，不重复，不引入未登记条目 |
| E07：每日一组 | 熟悉库有 4 个明确条目 | 当天使用 /复习、关闭并重新打开，再使用 /复习 | 每组为 3 个不同的熟悉条目；当天可恢复同一组；次日生成新一组，不要求它一定与前一天不同 |
| E08：撤销与非命令文本 | Python print 已登记 | 普通提问“登记是什么意思”，再明确撤销 Python print 并查询 | 普通问句不改变熟悉库；撤销后资料保留；查询不再显示熟悉提示 |

评价应分别记录：程序运行是否正常、条目匹配是否正确、回答是否有依据、解释与示例是否正确、个人状态是否符合实际。HTTP 200 和生成结束标记不等于答案正确。后续逐步补充工具调用、停止上限、失败与版本差异场景。
