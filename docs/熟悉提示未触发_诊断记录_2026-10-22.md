# StudyDocs Retry：熟悉库已有条目，但问答后未显示提示

- 记录日期：2026-10-22
- 涉及模块：cli.py 的名称解析与熟悉提示分支
- 依据：用户提供的实际终端输出，以及本次对话中已有的 CLI 代码
- 状态：已完成原因分析并提出参考修改；尚未确认修改是否应用、未验证修改后的运行结果

## 1. 如何发现问题

用户提问后，程序读取了字典资料并显示回答，但没有显示熟悉提示。随后执行 /熟悉库，确认字典条目已经登记。

关键日志节选：

~~~text
> python 字典如何按值取值
执行搜索：'字典按键取值'，语言：'Python'
本次工具读取资料： ['python_dict_lookup.md']
本轮实际读取资料： python_dict_lookup.md
> /熟悉库
Python print
Python 字典按键取值
C 指针数组
~~~

问题是：熟悉库里已有字典条目，为什么问答后没有提示？

## 2. 先确认哪些环节正常工作

| 证据 | 支持的判断 | 不能据此判断 |
| --- | --- | --- |
| /熟悉库显示字典条目 | 已登记，且本次状态查询能读到它 | 问答后的提示条件必然成立 |
| 工具读取 python_dict_lookup.md | 检索和资料读取路径已经执行 | CLI 的名称解析也识别出了这个条目 |
| 显示回答和来源 | 本次获得了最终回答 | 模型准确理解了问题，或回答必然正确 |

因此应检查提示条件，不能直接判断熟悉库数据丢失。

## 3. 找到提示的触发条件

对话中的 CLI 代码是：

~~~python
filename = reslove_item(user_text)
if filename is not None and is_familiar(filename):
    print("该条目已在你的熟悉库中")
~~~

这要求两个条件同时成立：

1. 用户整句输入能被转换成资料文件名。
2. 得到的文件名已经登记在熟悉库中。

这里没有检查本轮检索到的 sources。检索成功，并不会自动让名称解析成功。

## 4. 用实际输入计算中间结果

名称解析函数是：

~~~python
def reslove_item(text):
    normalized = "".join(text.split()).lower()
    return ITEM_ALIASES.get(normalized)
~~~

字典条目的名称表键是：

~~~python
"python字典按键取值": "python_dict_lookup.md"
~~~

输入去空白后得到：

~~~text
python字典如何按值取值
~~~

名称表中保存的是：

~~~text
python字典按键取值
~~~

两者不同。因此按这份代码执行时，get() 返回 None，filename is not None 为假，提示分支不会执行。

**根因：去空白解决格式差异；名称表仍进行整串精确匹配，不能识别任意自然语言问句。**

## 5. 为什么检索成功，提示却没有出现

两条路径独立执行：

~~~text
用户问题 → 模型选择关键词 → search_docs → 实际读取资料

用户整句输入 → reslove_item 精确查名称表 → 熟悉提示条件
~~~

本次第一条路径找到了字典资料，第二条路径返回 None。这两个结果可以同时存在。

## 6. 建议的局部修改

如果希望普通问句结束后也能提示，可改为检查本轮实际读取的资料是否已经登记。

在 cli.py 普通问答成功分支中，用下面的代码替换旧提示分支：

~~~python
familiar_sources = []

for source in sources:
    if is_familiar(source):
        familiar_sources.append(source)

if familiar_sources:
    labels = [
        ITME_LABELS.get(source, source)
        for source in familiar_sources
    ]
    print(
        "本轮读取的资料中，已登记熟悉的条目：",
        "、".join(labels),
    )
~~~

这里沿用对话中现有的 ITME_LABELS 变量名。sources 来自 result["sources"]，保存实际读取的资料文件名；is_familiar() 检查该文件名是否已登记。

修改后的流程：

~~~text
sources 包含 python_dict_lookup.md
    → 检查是否已登记
    → 显示 Python 字典按键取值
~~~

提示文字明确说“本轮读取的资料”。它不表示程序已经理解了用户问题，也不表示检索资料一定相关或回答一定正确。名称解析函数继续用于 /登记、/取消登记、/查看 等需要指定条目的命令。

## 7. 另外区分按键与按值的问题

输入是“按值取值”，模型却按“通过键读取值”回答。

例如，给出键 Lin 读取 90，与给出值 90 查找对应的键，是不同任务。仅凭这次输入不能确定用户实际想问哪一种。

因此，读取字典资料和显示熟悉提示，都不能代替对问题理解及答案质量的核对。这个差异属于另一项效果问题，不改变本次提示条件的定位结果。

## 8. 修改后的验证方法

应用修改并重启 python cli.py 后，检查以下场景。这里列出的是预期，尚非修改后的实测结果。

| 场景 | 预期 |
| --- | --- |
| 本轮读取字典资料，且该资料已登记 | 提示 Python 字典按键取值已登记 |
| 本轮读取字典资料，但该资料未登记 | 不显示该条目的熟悉提示 |
| 本轮没有读取资料 | 不显示基于本轮来源的提示 |
| 本轮读取多个资料，其中部分已登记 | 只显示其中已登记的条目 |
| 使用 /登记、/取消登记、/查看 | 继续通过原名称解析处理命令参数 |

同时观察“本轮实际读取资料”和 /熟悉库 输出，确认提示使用的是对应文件。
